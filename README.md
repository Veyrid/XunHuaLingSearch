# 寻花令 · 诗词检索

直接双击本目录的 **index.html**，用 Edge、Chrome 等现代浏览器打开。无需安装软件、启动服务或联网。请保留完整的 `dist` 文件夹；也可以把整个 `dist` 文件夹复制到另一台电脑，再打开其中的 `index.html`。

页面打开及编辑条件时不读取大词库。先选择朝代、填写条件，再点击 **开始检索**；之后每次修改条件也需再次点击。选择朝代可减少首次读取的数据；已有少量候选后继续增加条件，会尽量直接复用结果。完整收录说明见 [数据来源](dist/数据来源.md)。

## 如何筛选

- **上下句字数**：五言为上句 5 字、下句 5 字；七言为各 7 字。不限或分别自定义每句 1–40 字，标点不计入字数。
- **朝代**：可多选，选中的朝代取并集，再与其他条件同时筛选；不选或点击“不限朝代”恢复全部范围。“汉末”归入汉，“明末清初”在明、清中都能找到，结果保留原始标签。
- **整副必须包含**：填写 `明月` 表示两个字都要在上下句整体中出现；填写 `月月` 表示整副至少有两个“月”。展开“分别限定上句 / 下句的字”可单独限制每句。
- **整副不能包含**：填写 `风雨雪`，两句都不能出现这三个字。也支持只从某句排除。
- **字与位置确定**：先选上句或下句，再填写字与位置。例如“上句／处／1,2”表示上句第 1、2 字都是“处”；下句的位置另外从 1 开始。
- **有字但错位**：例如“上句／月明／1,3”表示两字在整副出现，但都不能在上句第 1、3 位，允许只出现在下句。若还要求字在上句出现，请同时填写“上句必须包含”。可添加任意多条上下句条件。

所有字段、所有位置条件和所有完整反馈同时生效，取交集。位置从 **1** 开始。冲突或未填完整的条件会提示原因，不会悄悄忽略。页面带有可一键填入条件的“明月”示例，填入后点击“开始检索”。

## 直接录入游戏反馈

展开“录入一轮寻花令反馈”，分别输入猜过的上句、下句并添加。点击每个字，依次切换：未设置 → 灰色 → 黄色 → 绿色 → 未设置。上下两句全部设置后才作为一轮参与筛选，可以添加多轮；标完后点击“开始检索”。

按你确认的规则，上下句作为一个整体判断存在和重复次数。默认使用 Wordle 规则：先分配两句所有正确位置，再按上句到下句、从左到右，根据整副剩余次数分配黄色。重复字既有彩色也有灰色时，灰色表示多猜了一次，不能把这个字全局排除。若游戏只按是否存在判断重复字，可改选“逐字判断”。

## 结果与用字

结果成对显示上下句、作者及题名，可一起复制，点击题名可查看全文。**上下两句文字均相同的结果只显示一次**，不同出处合并并可逐个查看；只有上句相同、下句不同的结果不会合并。默认将词库和输入一起转成简体匹配，再按简体去重；原文模式按原始用字匹配、去重。

**结果默认按朝代由早到晚排列**，同一结果的出处也依此排序；合并结果以当前符合条件的最早出处为准。朝代筛选先作用于每个出处，再合并相同上下句，因此选宋代时不会把其他朝代出处混入显示。宋、辽、金等并存时期使用固定的大致顺序，过渡标签单独安排位置，不推断具体创作年份。同朝代使用固定的来源顺序，加载顺序不会改变排序。

本地词库有 **745,625 首可配对作品**，严格模式索引 **3,580,312 条**来源记录，宽松模式共 **6,786,179 条**。记录按出处计数，搜索结果会再去重，并非游戏官方题库。

在原有唐诗、宋诗、宋词、诗经等资料之外，本次新增 **413,588 首**可配对作品，补充先秦、汉、魏晋、南北朝、隋、辽、金、元、明、清及交替时期。已验证“浩荡离愁白日斜／吟鞭东指即天涯”，以及《古诗十九首》《江南》《长歌行》《上邪》《木兰诗》《孔雀东南飞》《敕勒歌》等典型作品中的上下句。

## 严格配对与宽松补查

默认使用 **严格配对**，优先按来源段落和句末边界组成上下句，不再把每一对相邻分句都作为正常上下句。例如保留“忽如一夜春风来／千树万树梨花开”及“散入珠帘湿罗幕／狐裘不暖锦衾薄”，排除它们中间的跨联组合。

同时兼顾以下情况：

- **词与古体诗**：保留原段中的不等长上下句；恢复分成单句段落的两句、明确的等长平行短句。整齐诗行可按固定顺序恢复。“我欲乘风归去／又恐琼楼玉宇”能保留，剩余“高处不胜寒”不会接到下一段。
- **标点与分行差异**：原段的两句结构可以覆盖句末误用逗号、联中问号；同段多联按句末拆开。对没有唯一配法的三句同长、词中分片不明等情况保守省略，避免仅凭全篇奇偶位置强行配对。
- **句内停顿与领字**：顿号不独立拆句，“念去去、千里烟波”按完整 7 字句检索。明确的短领字逗号异文只在恢复等长时接回。冒号前的题记或引语作为断点，不机械粘到正文。全文保留来源用字；少量核对过的断句会显示整理说明和参考链接。

**所有相邻句（宽松）**保留同一作品内的相邻组合和恢复的完整句，适合找不到时补查。切换模式保留现有字数、位置、包含/排除及游戏反馈；严格模式没有结果时可一键切换。宽松可能出现跨联组合，应查看全文确认。两种模式都不跨作品、显式空行、缺字或无效片段拼接。

配对前保留重复句，例如“知否／知否”；筛选配对模式后才去重、合并该模式下的出处。严格规则是基于文本结构的推断，无法完全替代词谱和人工校勘，仍可能漏检或误判。

检索在浏览器内完成，不向搜韵或应用服务器提交查询条件和游戏反馈。在线版会按需下载本站的词库文件，托管平台会处理正常的页面及文件请求；离线版使用完整本地文件。外部来源链接仅在主动点击时打开。

## 检索速度

- 每个数据分块都带有朝代摘要，严格与宽松模式分别记录。选择朝代后，先跳过不相关的文件，再核对每条出处；没有摘要的旧分块仍会读取，避免漏检。
- 只对已完整检索的候选进行复用。增加包含次数、排除字、定位或排位、完成新一轮反馈、缩小朝代范围时，若可以确认所有旧条件仍然成立，就直接继续筛选。放宽条件、改字数、切换简繁或严格／宽松模式，或修改已有完整反馈时，重新查库。
- 未完成、出错或被新查询中断的搜索不能作为复用依据。反馈快照独立保存，点击反馈格不会悄悄改变旧条件。
- 页面最多缓存 24 个原始分块，先处理已有缓存，再分批读取新文件；每批最多 3 个。完整候选缓存上限为 75,000 个结果、150,000 个出处，超过时下次重新检索，不限制实际返回结果数量。
- 单次出现的字先快速核对，只有重复字才统计次数；完整反馈仍遵循整副 Wordle 规则。页面会显示本次检索用时。首次不限朝代的搜索仍可能需要几秒，具体取决于设备及本地文件读取速度。

## 开发与数据重建

网站是纯 HTML/CSS/JavaScript，无框架及运行时安装要求。`dist` 即完整可携带版本，也是 GitHub Pages 的发布目录。

- `dist/engine.js`：无 DOM 依赖的条件编译与反馈算法。
- `dist/dynasties.js`：朝代归类、大致年代顺序、出处排序与分块朝代摘要。
- `dist/search.js`：朝代预筛、分批读取、完整候选复用及取消过时搜索。
- `dist/couplets.js`：上下句界面、朝代多选、简繁转换、分页与出处全文。
- `dist/data/manifest.json`：准确统计、文件列表、两套数据的版本与实际下载快照 SHA-256。
- `data-sources.lock.json`：固定数据源版本、正式下载地址和朝代白名单。
- `sources/reading-corrections.json`：23 项可复核的断句或朝代整理，按作者、题名及原文哈希精确应用。
- `scripts/pairing.cjs`：保留来源边界，生成严格证据与宽松候选。
- `scripts/prepare-data.py`：从固定版本的正式 GitHub 压缩包恢复构建缓存，只读取指定数据文件，不执行仓库中的脚本。
- `scripts/build-data.cjs`：从准备好的两套数据离线生成词库。
- `tests/search.test.cjs`、`tests/pairing.test.cjs`、`tests/catalog.test.cjs`：共 39 项核心测试，覆盖条件/重复字反馈、上下句边界、词例、标点、缺字屏障、朝代排序、出处筛选、候选复用及回查完整性。
- `tests/ui.test.cjs`：2 项页面回归测试，确保初次打开、编辑和清空不读取词库，点击检索才执行最新条件；冲突条件不会查库。
- `scripts/check-pages.cjs`：发布体积、文件完整性、路径大小写及第三方许可检查。
- `tests/prepare-data.test.py`：6 项数据准备测试，覆盖格式、缺字、体裁、合集去重、整理校验及中断后不会误用未完成缓存。
- `scripts/benchmark-search.cjs`：对真实词库进行只读检索测量，检查复用与重新扫描结果完全一致。命令行耗时不等同于浏览器耗时。

**普通打开网页不需要 `.cache`、`node_modules`、Python 或 Node.js。** 下载包、解压目录、中间数据、未使用的搜韵下载残片及可重新安装的构建依赖已经清理。一次性朝代索引升级脚本已删除，正式构建流程会自动生成朝代摘要。`dist` 内保留当前完整词库与许可；开发源码、锁定文件、整理记录及验证工具仍保留。

需要重建时，使用 Python 3.11 或更高版本、Node.js 和 pnpm。在项目目录先恢复锁定的构建依赖，再依次运行：

```powershell
pnpm install --frozen-lockfile
python scripts/prepare-data.py --download
node scripts/build-data.cjs
node scripts/validate-data.cjs
```

依赖安装按 `pnpm-lock.yaml` 恢复固定版本；有本地包缓存时可复用，否则需要联网。准备数据的步骤仅在缺少压缩包时下载两份正式快照，并核对版本；已有压缩包时可去掉 `--download` 离线准备。源版本与正式地址保存在 `data-sources.lock.json`；压缩包文件名不同可能改变压缩包哈希，准备流程以包内提交版本核对并记录实际哈希。重建时不要同时使用旧页面；完成后刷新。重建完成并通过校验后，`.cache` 和 `node_modules` 可再次清理，但不要删除 `sources`、锁定文件或当前 `dist/data`。现有功能测试、全库检查、性能测试与本机预览不需要安装构建依赖。

测试：`node --test tests/search.test.cjs tests/pairing.test.cjs tests/catalog.test.cjs tests/ui.test.cjs`、`python tests/prepare-data.test.py`。全库完整性检查：`node scripts/validate-data.cjs`。可选预览：`node scripts/preview.cjs`，仅绑定 `127.0.0.1:5173`；普通使用不需要它。

提供渐进增强的 `set_poetry_filters` WebMCP 接口，可通过 `dynasties` 数组多选朝代，空数组或省略表示不限；不支持 WebMCP 的浏览器仍可完整使用界面。

## 发布到 GitHub Pages

目标仓库：[Veyrid/XunHuaLingSearch](https://github.com/Veyrid/XunHuaLingSearch)。启用并部署成功后的地址是 `https://veyrid.github.io/XunHuaLingSearch/`。

1. 将项目源码、`dist`、数据、现有第三方许可和 `.github/workflows/pages.yml` 一起推送到仓库。不要上传 `.cache`、`node_modules` 或本地 QA 文件。
2. 在仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
3. 默认分支有新提交时自动发布；也可在 **Actions → Check and publish GitHub Pages → Run workflow** 选择默认分支手动运行。等待 `check` 与 `deploy` 都成功后访问网站。

工作流执行功能测试、数据准备测试、发布文件检查和全库完整性检查，再仅将 `dist` 上传为 Pages artifact；不安装构建依赖、不重新下载数据、不重新生成词库。Pull request 和非默认分支只检查，不发布。发布 job 使用 GitHub 自动提供的权限，无需额外填写 token。

根目录 `index.html` 用于本地跳转；Pages 直接使用 `dist/index.html` 作为首页。所有静态资源和动态词库使用相对路径，支持 `/XunHuaLingSearch/` 项目子目录。可用 `node scripts/preview.cjs /XunHuaLingSearch/` 在本机复核相同路径。

当前完整站点约 **818 MB**，低于 GitHub Pages 的 **1 GB** 发布上限；`node scripts/check-pages.cjs` 会检查体积、缺失文件、路径大小写及第三方许可。后续扩库应再次检查体积。普通用户首次不限朝代检索五言约读取 202 MB、七言约 263 MB（文件原始大小，实际传输会受 HTTP 压缩及浏览器缓存影响）；打开页面不会自动下载这些词库。选择朝代可以减少读取量，仅填写文字或位置不会减少首次扫描涉及的分块数量。

GitHub 官方说明：[发布来源](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)、[自定义工作流](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)、[Pages 限制](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)。
